# Validation plan

## Foundation

Check recovered starter text, relative document links, whitespace, and preservation of original
repository files. No dependency installation or functional application tests apply at this stage.

## Prototype

Run the future documented root check command. Numerical tests must assert independently
calculated expectations from modelling.md, rather than duplicate the implementation.
Exercise catalogue changes, shared instances, deletion constraints, invalid input, source
movement, receptor queries, empty scenes, cloud metadata, and provider failures.

Inspect the browser at a desktop viewport and a narrow viewport. Confirm readable controls,
visible attribution, map/source drag distinction, legend units, keyboard-accessible editing,
and accessible numeric results alongside the colour overlay. Capture and inspect screenshots.

A successful build or passing unit suite does not establish the accuracy of the physical model.
A satellite layer loading does not establish permission to use it.

## Field validation, later

Define operating scenarios and receptor locations with measured source/background data.
Compare predictions against observations under documented conditions. Record errors and
uncertainty. Seek suitable acoustic expertise before using results as evidence of inaudibility.
